Markdoc

  • View as Markdown
  • Open in ChatGPT
  • Open in Claude

Markdoc is Markdown with tags. Name the file .markdoc. Headings, the table of contents and code blocks work as in Markdown, and these tags add components. Each example below shows the source, then the result.

Callout

Section titled “Callout”

Good to know

Sandbox keys start with sk_test_.

type is one of note, info, tip, success, caution, warning, danger, sparkles, rocket, settings, zap, lock, megaphone. icon picks any other Phosphor icon. See Callouts.

Workflow

Section titled “Workflow”

Draws one workflow of a file in workflows:: file is the entry's id, id the workflowId in the file (default: its first workflow), view is expanded (the default) or compact, and title a caption. The tag shows the workflow runner: the diagram with a panel for the inputs and credentials, and Run workflow executes the steps from the browser. The same diagram is also generated at build time, so it shows while the runner loads and without JavaScript.

More tags

Section titled “More tags”
TagDoes
asideThe same as callout.

filetreeA folder tree, drawn from the nested list inside it.

Showing tag source in a code block

Section titled “Showing tag source in a code block”

A code fence shows its content as text, tags included, so the examples on this page are plain fences. Markdoc still checks the tags inside a fence, though: an unknown tag or attribute fails the build even inside a code block.

To show tags that aren't valid here, such as a tag from another site or a made-up example, turn the check off with Markdoc's process=false annotation after the language:
